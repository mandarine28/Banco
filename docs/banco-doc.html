🏠 Vue d'ensemble

Banco est un jeu de société mobile multijoueur en local (sur un seul appareil). Les équipes s'affrontent en se lançant des enchères : combien de réponses à une question de culture générale peuvent-elles citer en 60 secondes ? L'équipe qui enchérit le plus haut doit tenir sa promesse, sinon l'adversaire empoche les points.

L'application est construite avec Expo (React Native géré) et déployée sur l'App Store via EAS Build. Elle utilise Supabase pour l'authentification des utilisateurs et RevenueCat pour gérer les achats intégrés (packs de questions).

🎯 Concept

Jeu d'enchères + culture générale. 2 à 4 équipes, 1 à 10 rounds, 60 secondes pour répondre.

🌍 Langues

Français, Anglais, Allemand, Espagnol. Interface et réponses traduites.

📦 Technologie

Expo SDK 57 · React Native 0.86 · TypeScript · Expo Router (file-based navigation)

💰 Monétisation

Packs de questions payants via achats intégrés non-consommables (0,99€). Publicité prévue en complément (voir Publicité).

Rôle détaillé de chaque acteur

🟢 Supabase — La base de données & l'authentification

Supabase est le cerveau côté serveur de Banco. C'est lui qui sait qui sont les utilisateurs et stocke toutes les données persistantes.

  • Authentification : gère la connexion des joueurs (email/mot de passe, Apple Sign In, Google). À chaque connexion, il génère un token JWT qui prouve l'identité de l'utilisateur.
  • Sessions : conserve la session active entre les ouvertures de l'app. L'utilisateur n'a pas à se reconnecter à chaque fois.
  • Base de données PostgreSQL : stocke les données des joueurs (scores, historique de parties). Protégée par des règles RLS (Row Level Security) — chaque utilisateur ne voit que ses propres données.
  • Dans le code : src/lib/supabase.ts configure le client, src/state/auth.tsx expose le hook useAuth() utilisé partout dans l'app.

🟠 RevenueCat — Le gestionnaire d'achats

RevenueCat est le pont entre l'app et l'App Store pour tout ce qui concerne les paiements. Il abstrait la complexité de StoreKit (l'API Apple) pour la rendre simple à utiliser.

  • Produits : fait le lien avec les IDs de produits définis dans App Store Connect (ex: com.banco.pack_harry_potter).
  • Entitlements : après un achat validé par Apple, RevenueCat active un "droit" (ex: pack_harry_potter). L'app vérifie ce droit pour décider si le contenu est débloqué.
  • Restauration : si l'utilisateur change de téléphone ou réinstalle l'app, RevenueCat retrouve ses achats passés chez Apple et réactive les entitlements.
  • Offerings : groupe les produits en "offres" que l'app récupère via SDK pour afficher dans la boutique.
  • Dans le code : src/lib/revenuecat.ts initialise le SDK, src/state/purchases.tsx expose usePurchases() avec hasPurchased(), purchase(), restorePurchases().

🍎 App Store Connect — La plateforme Apple

App Store Connect est le tableau de bord officiel d'Apple pour les développeurs. C'est la source de vérité pour tout ce qui concerne la distribution de l'app.

  • Achats intégrés (IAP) : c'est ici que chaque produit payant est déclaré avec son ID, son prix, son type et sa description. Apple est le seul à pouvoir encaisser l'argent.
  • TestFlight : outil de bêta-test d'Apple. Les builds compilés par EAS sont envoyés ici pour être testés avant publication officielle.
  • Fiscalité : contrats et formulaires fiscaux (W-8BEN pour les non-résidents américains), compte bancaire pour recevoir les paiements, Small Business Program (commission réduite à 15%).
  • Review Apple : avant chaque publication sur l'App Store, Apple vérifie manuellement l'app (2–3 jours en moyenne).
  • Clé IAP (.p8) : fichier de sécurité qui permet à RevenueCat de valider les transactions directement avec les serveurs Apple (StoreKit 2).

🔵 EAS Build — La chaîne de compilation

EAS (Expo Application Services) est le service de build cloud d'Expo. Il compile le code React Native en une vraie app iOS (.ipa) sans avoir besoin d'un Mac.

  • eas build : compile l'app dans le cloud. Prend ~10–15 min. Génère un fichier .ipa (iOS) signé avec les certificats Apple.
  • eas submit : envoie automatiquement le .ipa compilé vers TestFlight. Aucune action manuelle requise.
  • Profils de build : définis dans eas.json — development pour le simulateur, preview pour TestFlight, production pour l'App Store.
  • Variables d'environnement : les clés secrètes (Supabase, RevenueCat) sont injectées au moment du build depuis le fichier .env local — elles ne sont jamais commitées sur Git.
  • Certificats : EAS gère automatiquement les certificats de signature Apple (provisioning profiles, certificates). Tout est stocké côté Expo, pas à gérer manuellement.

Comment ça fonctionne dans le code

// 1. RevenueCat est initialisé au démarrage avec la clé iOS
initRevenueCat(userId);

// 2. Pour acheter un pack :
const offerings = await rc.getOfferings();           // récupère l'offering default
const pkg = offerings.current?.availablePackages     // trouve le bon package
  .find(p => p.product.identifier === 'com.banco.pack_harry_potter');
const { customerInfo } = await rc.purchasePackage(pkg); // déclenche Apple Pay

// 3. Pour vérifier si l'utilisateur a déjà acheté :
hasEntitlement(customerInfo, 'pack_harry_potter')    // → true/false
💡 Le code vérifie toujours l'entitlement, pas le Product ID. Ça permet d'attacher plusieurs produits au même droit plus tard (ex: pack bundle).

🗄️ Supabase

Supabase est le backend de l'app. C'est une alternative open-source à Firebase qui fournit une base de données PostgreSQL, un système d'authentification et une API REST automatique.

🔐 Authentification

Gère les comptes utilisateurs. Méthodes disponibles :

• Email + mot de passe
• Apple Sign In
• Google Sign In

💾 Base de données

PostgreSQL hébergé. Accès sécurisé via Row Level Security (RLS) — chaque utilisateur ne voit que ses propres données.

Stockage des sessions

Les tokens JWT de session sont stockés de façon sécurisée sur l'appareil via expo-secure-store (Keychain iOS / Keystore Android). Les tokens trop grands (>2Ko) basculent automatiquement sur AsyncStorage. 

// supabase.ts — Stockage hybride sécurisé
const LargeSecureStore = {
  async getItem(key) { ... },  // SecureStore avec fallback AsyncStorage
  async setItem(key, value) {
    if (value.length > 2000) {
      await AsyncStorage.setItem(key, value);  // tokens trop grands
    } else {
      await SecureStore.setItemAsync(key, value); // tokens normaux
    }
  }
}

Les phases d'un round

🔔 auction
Les équipes enchérissent. Combien de réponses peut-on citer ?
✋ ready
L'enchère est remportée. L'équipe se prépare.
▶️ play

Points attribués. Succès ou échec.

Dernier round joué. Classement final.

Règles de points

✅ Succès (l'équipe atteint sa mise) : chaque équipe qui a enchéri empoche sa propre mise.

❌ Échec (l'équipe n'atteint pas sa mise) : l'adversaire empoche la mise la plus haute.

🛒 Achats intégrés (IAP)

IAP = In-App Purchase. Ce sont les achats effectués directement dans l'application. Apple gère la transaction bancaire, RevenueCat gère les droits utilisateur, et l'app vérifie ces droits.

Flux complet d'un achat

1. Utilisateur ouvre la Boutique
→
2. Clique "Débloquer le pack"
→
3. RevenueCat fetche l'offering
→
4. Apple Pay s'ouvre (0,99€)
5. Apple valide le paiement
→
6. RevenueCat active l'entitlement
→
7. Pack débloqué ✓

Comment le code vérifie un achat

// state/purchases.tsx
const hasPurchased = (productId: ProductId): boolean => {
  if (!customerInfo) return false;
  // Vérifie si l'entitlement est actif dans RevenueCat
  return hasEntitlement(customerInfo, ENTITLEMENT_IDS[productId]);
};

// Exemple d'utilisation dans parametres-partie.tsx
const { hasPurchased } = usePurchases();
const hasHarryPotter = hasPurchased('packHarryPotter'); // → true/false

Restauration des achats

Apple exige que les apps proposent un bouton "Restaurer les achats". Quand l'utilisateur appuie dessus, RevenueCat recontacte Apple pour récupérer l'historique d'achat et réactiver les entitlements.

Test en sandbox

Avant de payer réellement, tester avec un compte sandbox Apple (App Store Connect → Utilisateurs et accès → Sandbox). Aucune carte n'est débitée, le flux est identique à la vraie production.

🔑 Variables d'environnement

Les variables d'environnement sont stockées dans un fichier .env à la racine du projet (jamais commité sur Git). Copier .env.example pour créer le fichier.

⚠️ Ne jamais partager ou committer le fichier .env. Il est dans .gitignore.
EXPO_PUBLIC_SUPABASE_URL
URL du projet Supabase. Format : https://xxxxx.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY
Clé publique Supabase (anon key). Commence par eyJ.... Protégée par RLS côté serveur.
EXPO_PUBLIC_REVENUECAT_IOS_KEY
Clé SDK publique RevenueCat pour iOS. Commence par appl_. Trouvable dans RevenueCat → Project Settings → API Keys.
EXPO_PUBLIC_REVENUECAT_ANDROID_KEY
Clé SDK publique RevenueCat pour Android. Commence par goog_. Optionnel si Android non déployé.
EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID
Client ID OAuth Google pour iOS. Google Cloud Console → OAuth 2.0 → iOS Client ID.
💡 Toutes les variables commencent par EXPO_PUBLIC_ car elles sont incluses dans le bundle de l'app. Ne jamais y mettre de secrets privés (clés privées, tokens d'admin, etc.).

📖 Glossaire

Les termes techniques expliqués simplement.

SDK Software Development Kit
Boîte à outils fournie par un service pour l'intégrer dans une app. RevenueCat fournit un SDK React Native, Supabase aussi. Ça évite de coder les appels réseau à la main.
IAP In-App Purchase
Achat effectué à l'intérieur d'une application mobile. Apple prend 15-30% de commission sur chaque vente. Les IAP non-consommables sont achetés une seule fois et gardés à vie.
Bundle ID Bundle Identifier
Identifiant unique de l'app dans l'écosystème Apple. Banco utilise com.mandarine.banco. Impossible à changer une fois l'app publiée. Format: domaine inversé + nom de l'app.
Entitlement
Dans RevenueCat, c'est le "droit" qu'un utilisateur obtient après un achat. Ex: après avoir acheté le Pack Harry Potter, l'utilisateur obtient l'entitlement pack_harry_potter. L'app vérifie l'entitlement (pas le produit directement) pour savoir si le contenu est débloqué.
Offering (RevenueCat)
Un groupe de produits IAP présentés ensemble à l'utilisateur. L'offering "default" est celle que l'app charge automatiquement. Ça permet de changer les produits proposés sans mettre à jour l'app.
EAS Expo Application Services
Service cloud d'Expo qui compile, signe et distribue l'app. Permet de builder une app iOS sans avoir un Mac ni Xcode. Les builds se font sur les serveurs d'Expo.
StoreKit
Le framework Apple qui gère les achats in-app. StoreKit 2 (la version moderne) est ce qu'utilise Banco via RevenueCat. C'est lui qui affiche la fenêtre Apple Pay.
Sandbox (Apple)
Environnement de test Apple où les achats ne sont pas réels. On crée un "compte testeur sandbox" et on peut acheter sans être débité. Indispensable pour tester les IAP avant la mise en production.
TestFlight
Application Apple pour distribuer des versions bêta d'une app à des testeurs. L'app est soumise une fois à Apple, puis accessible via l'app TestFlight sur iPhone. Étape avant la publication officielle sur l'App Store.
JWT JSON Web Token
Un token (jeton) d'authentification. Supabase en génère un quand l'utilisateur se connecte. Il est stocké sur l'appareil et envoyé à chaque requête pour prouver l'identité de l'utilisateur. Il expire après un certain temps et est automatiquement renouvelé.
RLS Row Level Security
Système de sécurité PostgreSQL (Supabase) qui fait que chaque utilisateur ne peut lire/modifier que ses propres données dans la base de données. Même si la clé anon est publique, les données restent sécurisées.
Reducer (pattern)
Pattern de programmation utilisé dans le moteur de jeu. Une fonction prend (état actuel + action) et retourne un nouvel état. Aucune modification directe. Facile à tester et à déboguer.
Expo Router
Système de navigation de Banco. Chaque fichier dans src/app/ devient automatiquement une route. index.tsx = page d'accueil, boutique.tsx = page /boutique, etc.
Context / Provider (React)
Mécanisme React pour partager des données entre tous les écrans sans les passer manuellement. Banco utilise AuthProvider (session), PurchasesProvider (achats), GameSettingsProvider (paramètres de partie). On accède aux données avec useAuth(), usePurchases(), useGameSettings().
Achat non-consommable
Type d'IAP acheté une seule fois, à vie. L'utilisateur peut toujours le restaurer en changeant de téléphone. Par opposition aux consommables (pièces de jeu, vies) qui s'épuisent.
SecureStore / AsyncStorage
Systèmes de stockage local sur l'appareil. SecureStore = stockage chiffré (Keychain iOS) pour les données sensibles comme les tokens. AsyncStorage = stockage non chiffré pour les données moins sensibles.
Clé .p8 (Apple)
Fichier de clé privée Apple utilisé pour authentifier les requêtes entre RevenueCat et Apple (StoreKit 2). Ne jamais partager ni committer. Apple ne permet de le télécharger qu'une seule fois. Il existe deux types : clé API App Store Connect (pour EAS) et clé In-App Purchase (pour RevenueCat).
W-8BEN
Formulaire fiscal américain signé par les non-résidents US pour bénéficier du traité fiscal France-USA. Permet d'avoir un taux de retenue à la source de 0% sur les revenus App Store au lieu de 30%.
Régie publicitaire Ad network
L'entreprise qui fournit les pubs et paie l'éditeur de l'app : Google AdMob, AppLovin, Unity…
Annonceur
La marque qui paie pour que sa pub soit diffusée (un autre jeu, une appli, une marque…).
AdMob
La régie publicitaire de Google. Gratuite à intégrer : elle se rémunère sur une part des revenus. C'est le choix de départ pour Banco.
Médiation
Un système qui met plusieurs régies en concurrence sur chaque pub affichée, pour vendre l'emplacement au plus offrant. AdMob a sa propre médiation ; AppLovin MAX et Unity LevelPlay sont des plateformes de médiation.
Enchères en temps réel Bidding
La méthode de la médiation : à chaque pub, les régies font une offre en quelques millisecondes et la meilleure gagne.
Lock-in
Le fait d'être « enfermé » chez un fournisseur parce qu'en changer coûte cher ou est compliqué.
eCPM Effective Cost Per Mille
Ce que l'éditeur gagne pour 1 000 pubs affichées. L'indicateur principal pour comparer régies et formats.
Taux de remplissage Fill rate
Le pourcentage de fois où une pub est réellement disponible quand on en demande une. À 90 %, une demande sur dix ne trouve pas de pub.
Pays « Tier 1 »
Les pays où les pubs rapportent le plus (États-Unis, Royaume-Uni, Canada, Australie, Allemagne…). Selon les sources, la France est classée Tier 1 ou Tier 2.
ROAS Return On Ad Spend
La rentabilité d'une campagne pour l'annonceur, pas pour l'éditeur de l'app.
Rétention
La part des joueurs qui reviennent dans l'app (après 1 jour, 7 jours, 30 jours…).
Plafond de fréquence Frequency capping
Réglage AdMob qui limite le nombre de pubs montrées à un même joueur (ex. 1 toutes les 10 minutes).
RGPD Règlement général sur la protection des données
La loi européenne sur les données personnelles. Elle oblige à demander l'accord du joueur avant de lui montrer des pubs personnalisées.
UMP User Messaging Platform
L'outil gratuit de Google qui affiche le message de consentement RGPD (« Accepter / Refuser / Gérer »).
ATT App Tracking Transparency
La fenêtre d'Apple « Autoriser l'app à suivre vos activités ? ». Obligatoire sur iPhone si les pubs utilisent ce suivi.
app-ads.txt
Un petit fichier texte à publier sur le site de l'éditeur. Il prouve aux annonceurs que l'app est bien la sienne, ce qui évite la fraude. Sans lui, les pubs rapportent moins.
Étiquettes de confidentialité / Sécurité des données
Les sections des fiches App Store et Play Store où l'on déclare les données collectées par l'app. La publicité doit y figurer.
Code natif
Du code propre à iOS ou Android, en dehors du JavaScript. Les SDK de pub et RevenueCat en contiennent.
Mise à jour OTA Over The Air
Une mise à jour envoyée directement aux joueurs sans passer par les stores. Impossible pour ajouter du code natif (comme un SDK de pub) : il faut alors un nouveau build.
Expo Go
L'app de test d'Expo. Elle ne contient que les modules natifs d'Expo : impossible d'y tester des pubs ou des achats. Il faut un « build de développement ».
Config plugin
Un réglage dans app.json qui configure automatiquement la partie native d'une bibliothèque.
Identifiants de test (pub)
Codes fournis par Google qui affichent de fausses pubs pendant le développement, pour éviter une suspension du compte pour clics frauduleux.
Interstitiel Interstitial
Pub plein écran imposée entre deux écrans. Variantes : image (croix rapide), vidéo passable, vidéo non passable, jouable, rich media. Pour Banco : image seulement, en fin de partie.
Vidéo récompensée Rewarded
Le joueur choisit de regarder une pub (15 à 30 s) en échange d'une récompense. Le format le mieux accepté et le plus rentable. Pour Banco : essayer un pack payant.
Interstitiel récompensé Rewarded interstitial
Pub affichée à un moment naturel, annoncée par un écran qui présente la récompense et laisse quelques secondes pour refuser.
Bannière Banner
Bandeau publicitaire en haut ou en bas de l'écran (classique, adaptative ou repliable). Rapporte peu et abîme le design.
Pub native Native ad
Pub dont l'app dessine l'affichage avec les éléments fournis (titre, image, bouton), pour qu'elle s'intègre au design. Elle doit rester marquée « Pub ».
Pub à l'ouverture App open
Pub plein écran au lancement de l'app ou au retour dedans. Exclue pour Banco.
Offerwall
« Mur d'offres » : « Installe tel jeu ou atteins tel niveau pour gagner X ».
